## 🧮 Method — the formulas that make it work

### A. Convert dates correctly (the hint that trips most people)

In `Data`, two helper columns inside the `Sales` table:

```excel
Clean_Date  =IFERROR(DATEVALUE([@Date]), [@Date])      " text date → real date; already-date passes through
Month_Key   =TEXT([@Clean_Date], "YYYY-MM")             " 2023-01 … 2023-12  ← the SORTABLE key
```

> 💡 Why `YYYY-MM` and not `MMM`: a month *name* sorts alphabetically
> (Apr, Aug, Dec, Feb, Jan …) and silently scrambles the trend line. The zero-padded
> `YYYY-MM` string sorts in true calendar order, and a separate display label is added later.

### B. The monthly summary table (`Monthly_Trend`, rows 2–13)

| Column | Header | Formula (row 2, fill down) | Format |
|---|---|---|---|
| A | `Month_Key` | typed `2023-01 … 2023-12` (the sort spine) | text |
| B | `Total Sales` | `=SUMIFS(Sales[Total Amount], Sales[Month_Key], $A2)` | Currency `$#,##0.00` |
| C | `Transactions` | `=COUNTIFS(Sales[Month_Key], $A2)` | Number `#,##0` |
| D | `Avg Sale / Txn` | `=IFERROR(B2/C2, 0)` | Currency `$#,##0.00` |
| E | `Month_Label` | `=TEXT(DATEVALUE($A2 & "-01"), "mmm-yyyy")` | text (chart axis) |

The chart plots **E (labels) on the X-axis** and **B (sales) on the Y-axis** — labels for readability, key for ordering.

### C. The line chart

## ✅ Verification (`Validation` tab) — proving the conversion & the rollup

| Check | Formula | Expected |
|---|---|---|
| Dates are real numbers (not text) | `=SUMPRODUCT(--(ISTEXT(Sales[Clean_Date])))` | **0** |
| Every row has a usable date | `=COUNT(Sales[Clean_Date])` | **1,000** |
| Monthly sales reconcile to grand total | `=IF(ABS(SUM(B2:B13)-SUM(Sales[Total Amount]))<0.01,"✅ MATCH","❌ CHECK")` | ✅ |
| Monthly counts reconcile to row count | `=IF(SUM(C2:C13)=COUNTA(Sales[Transaction ID]),"✅ MATCH","❌ CHECK")` | ✅ (1,000) |
| Chronological order intact | `=IF(EXACT(A2:A13, SORT(A2:A13)),"✅ sorted","❌ check")` *(or eyeball: Jan→Dec)* | ✅ |

Three independent proofs: **type check** (dates are dates), **control-total reconciliation**
(months sum to the whole), and **order check** (the spine is calendar-sorted). A monthly table
that passes all three is trustworthy; one that fails the reconciliation usually means a date
slipped through as text and landed in no month bucket.

## 🚫 Common Mistakes Avoided (mapped to the hints)

| Mistake | Why it's wrong | What I did instead |
|---|---|---|
| Sorting by month *name* | Alphabetical order scrambles the timeline | `YYYY-MM` key as the sort spine |
| Trusting imported dates | CSV dates often arrive as text → SUMIFS returns 0 | `DATEVALUE` + `ISTEXT`/`COUNT` proof |
| Bar chart for a trend question | Bars compare categories; lines show change over time | Line with markers |
| Unhandled bad dates | A `NaT`/text date vanishes from every month bucket | Reconciliation check catches the gap |
| Grouping on the display label | `mmm-yyyy` strings don't sort chronologically either | Label for the axis, key for the order |

---

## 📚 Lessons Learned
- **Date conversion is the real task** in any "by month" analysis; the chart is the easy part.
- **Separate the sort key from the display label** — `YYYY-MM` orders, `mmm-yyyy` reads.
- **Reconcile the breakdown to the control total** every time (Day-16 habit): if months don't
  sum to the grand total, a date slipped through as text.
- **Match chart type to question** (Day-7 rule): trend over time → line, not bar, not pie.
- A second tool (pandas) agreeing with Excel is cheap insurance against a silent conversion bug.
